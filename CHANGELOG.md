# Changelog

## Unreleased

- The benchmark was repeated with a viral donor in place of the bacterial one. Precision is 0.989 over eighteen runs against 1.000 for a bacterial donor, with the errors appearing where chimeras are fewest rather than most. The virus used does not integrate and stands in for size and composition only.
- The benchmark can now simulate an RNA-seq library, with expression drawn across four orders of magnitude, reads sampled in proportion to it, and a spliced version whose reads cross exon boundaries. The answer is that hgt-site should not be used on RNA-seq: precision reaches 0.773 unspliced and 0.750 spliced, against 1.000 on DNA, and reads crossing exon junctions produce false sites of their own. Documented in the benchmarks rather than fixed.
- Documented that `--exclude-regions` excludes a candidate whose span overlaps a region, so it suits a handful of broad regions rather than a dense feature file. A blacklist of every exon boundary cut recall to 34 of 60 for no gain in precision.
- The benchmark now covers vectors and transgenes: constructs of 1 kb, 3 kb and 8 kb, called with `--donor` and no classifier. All 100 insertions across five runs were found with nothing false and every junction exact. Repeated with free construct present, so nine chance chimeras in ten carried the construct and 6,187 positions looked like candidates, the 20 real insertions were still the only ones reported.
- The benchmark now says what is wrong instead of raising a traceback when the requested insertion is longer than the donor, which is easy to hit with a small construct.
- The README now opens with the problem rather than the method, since the people who need this tool mostly do not think of themselves as studying horizontal gene transfer: they have bacterial or viral reads in a host sample and a list of positions they cannot triage. There is an animated terminal demo of a real session, generated by `scripts/make_demo_svg.py`, and the browser notebook is linked from the top.
- New nightly workflow installs the published Bioconda package and runs it against real public sequencing reads, checking the output is what that sample should give. Everything in the benchmarks is simulated, so this is the one check that says the thing people install still works on real data today.
- A draft preprint is in `manuscript/`. It has not been submitted and its references are not yet formatted.
- Every site now reports the base composition of its foreign reads against the host's own, as `gc_foreign`, `gc_difference` and `kmer_ratio`. The host background is taken from the host-mapped mates of the anchored pairs, so nothing extra is read. `kmer_ratio` divides the 3-mer distance by the distance sampling noise alone would give at that read count, so it is comparable between sites: around 1 means the reads are indistinguishable from host sequence, which usually means the classifier got them wrong. It is reported and not filtered on, because it does not separate real insertions from chance chimeras: on a benchmark run the real sites gave 2.86 to 6.72 and the false ones 2.85 to 3.94, since a chimera carries genuinely foreign sequence too.
- New `--local-background` option works out how many chance chimeras to expect at a site from host coverage near that site rather than from one genome-wide rate. A chimera's host half comes from the host DNA in the library, so a region at three copies contributes three times the chimeras, and the even assumption reads the excess as an insertion. With a 500 kb region at six copies, the default reported 69 sites across three seeds of which 10 were false, all inside that region; with this option the same runs reported 59 sites and none was false, with no true site lost. The expectation is only ever raised, never lowered, so the option can cost sensitivity and cannot cost precision; with no amplified region it reported exactly the same sites as the default on all three seeds. It needs the whole alignment rather than one filtered down to the pairs with an unmapped mate, which it checks for and says so. The ratio used is reported in a new `depth_ratio` column.
- The benchmark can put a region of the host genome into the sample at several copies, with the extra chance chimeras that follow, through `--amplify START:LENGTH:FACTOR`.
- New `--donor` option takes a FASTA of the sequence you are looking for, instead of classifier output. Someone who put the DNA there, a vector, a transgene or a known viral genome, should not have to build a Kraken2 database to find out where it went. The unmapped reads are matched against the donor directly by exact 31-mer matching in both orientations, at about 50,000 reads a second, and everything after that step is unchanged. `--donor-taxid` sets the taxid the reads are reported under, 32630 by default. `hgt-site simulate` now also writes the donor sequence, so the demo dataset can be called either way.
- New `--exclude-regions` option takes a BED file of positions to leave out, and a candidate overlapping one is reported with `EXCLUDED` in the filter column instead of passing. A protocol, a reference or a cell line tends to produce the same false site in every sample, and there is no point rediscovering it each time. The reads in an excluded region still count towards the genome-wide rate, because dropping them would lower that rate and make every other site look more surprising than it is.
- The benchmark can now draw a share of its chance chimeras from the donor rather than only from the contaminating genomes, which is what a sample containing free donor alongside the integrated copy does. With six chimeras in ten coming from the donor, precision stayed at 1.000 and recall fell from 1.000 to 0.933 as the chimera load rose. `--donor-chimera-fraction` defaults to 0, so every earlier result is unchanged.

- A Snakemake wrapper is in `snakemake/`, ready to submit to snakemake-wrappers, so the tool can be used from a Snakemake workflow.
- An nf-core module for `hgt-site call` is in `nextflow/`, ready to submit to nf-core/modules, so the tool can be dropped into a Nextflow pipeline. Not yet run, because neither Nextflow nor nf-test was available where it was written.

## 0.4.0 (2026-11-06)

- Per-read classifications no longer have to come from Kraken2. KrakenUniq, Kaiju, Centrifuge, DIAMOND `--outfmt 102` and BLAST tabular output are read directly, as is any two-column file of read name and taxid, gzipped or not. The format is detected from the file and `--classifier` overrides it. The option is now `--classifications`, with `--kraken` kept as an alias. Every format gives byte-identical output on the same reads, which the tests check.
- New `--annotation` option takes a GTF or GFF3 file and reports the gene each site falls in, or the nearest gene within `--max-gene-distance`, in three new columns and in the VCF as `GENE` and `GENEDIST`. A position on its own is hard to act on; the gene is the first thing anyone asks for.
- New `hgt-site cohort` command merges the per-sample tables into one, so a position seen in every sample, which is usually an artefact of the protocol or the reference, can be told from one seen in a few. It reads the tables rather than the alignments, so samples called at different times can be combined without rerunning anything, and `--matrix` writes a position by sample grid.
- New `hgt-site selftest` command builds a dataset with known insertion sites, calls it and checks the answers, so an installation can be shown to work before anyone spends time on their own data.
- hgt-site can now be used as a library: `from hgt_site import call_sites, passed, to_dataframe`. The public names are importable from the package itself, loaded on demand so `import hgt_site` stays fast, and documented with examples.
- The VCF now carries a `QUAL` score, the q-value on the phred scale, so the file can be filtered with `bcftools view -i 'QUAL>50'` instead of being parsed by hand.
- A junction estimated from read pairs now carries `CIPOS` and `CIEND`, saying how far the real junction could be from the reported position. A junction found in split reads is exact and carries no interval. This is the standard way to state positional uncertainty, and the SV comparison tools use it to decide whether two calls match.
- The VCF header records the exact command and every threshold used, as `##hgt_siteCommand` and `##hgt_siteSetting` lines, and `##contig` lines now carry contig lengths from the alignment header.
- The VCF has one sample column, named after the alignment or after `--sample-name`, with the supporting pair count in `PR` and the split-read count in `SR`. `GT` is always `./.`, because hgt-site counts reads supporting a junction and does not genotype it.
- A `--vcf` name ending in `.gz` is block compressed and indexed with tabix, so it can be queried by region.
- hgt-site is on Bioconda, so it installs with `conda install -c conda-forge -c bioconda hgt-site` and comes with a Docker and Singularity container built automatically.
- A Galaxy tool wrapper is in `galaxy/`, ready to submit to the Tool Shed now that the Bioconda package exists, so the tool can be run by people who do not use a command line.
- New documentation page on reading the results: which columns decide whether a site is worth following up, which sites to be sceptical of, and how to confirm one.
- Fixed: the command recorded in the VCF header came from `sys.argv`, so calling `main()` from another program recorded that program's arguments.

## 0.3.0 (2026-11-02)

- New `hgt-site run` command: give it a host alignment and a Kraken2 database and it pulls out the unmapped reads, classifies them with Kraken2 and calls the sites in one step. `hgt-site call` is unchanged, for reads a pipeline has already classified.
- Junctions are now exact where reads cross them. Reads that are soft-clipped at the junction place the insertion point to the base pair, reported in four new columns and used for the VCF position. In the benchmark, 71% of junctions were exact and 98% were within 2 bp, against 41% and 57% from read pairs alone. This needs an indexed BAM or CRAM; without an index the estimate from read pairs is kept. `--no-split-reads` turns it off.
- New `--multiqc` option writes a summary table that MultiQC picks up, so the counts appear in a pipeline report.
- `hgt-site simulate` also writes the host reference, so its reads can be stored as CRAM.
- Every option now has help text of its own.
- Documentation site at https://iraajgangavaram.github.io/hgt-site/

## 0.2.0 (2026-11-01)

- More than twice as fast on large BAM and CRAM files: reads whose pair is fully mapped are now skipped before any other work. A new `--threads` option uses more cores to read BAM and CRAM files.
- `--kraken` accepts several files, such as the two that nf-core/hgtseq writes for each sample.
- New `--bed` option writes the sites that passed every filter as a BED file.
- New `--vcf` option writes every candidate site as a VCF 4.2 insertion record, with PASS or the failing flags in FILTER.
- Clustering limits are widened automatically for libraries with fragments longer than about 500 bp, using fragment sizes measured from properly paired reads.
- hgt-site now reports how many anchored pairs it found and how many have a Kraken2 call, and warns if the Kraken2 file does not seem to match the alignment.
- `hgt-site simulate` now fills in mate positions and marks properly paired reads, so its SAM files convert cleanly to BAM.
- Python 3.10 or newer is now needed. Python 3.9 no longer gets security updates.
